BUG ID: BUG-0004
TITLE: Hackathon Mission Runner Copies Static Fixture Report Instead of Dynamically Re-Simulating Authored Mission
SEVERITY: S1 - CRITICAL
CATEGORY: SIMULATION / FALSE_SUCCESS
STATUS: RESOLVED (Verified in Review Cycle 4 by commit e3d8721)

ENVIRONMENT:
- SkyTrack Version: 1.2.2
- MCP Commit: f0a1850
- World: urban
- UAV: x500_tennis_balls
- File: evals/run_hackathon_mission.py, src/skytrack_mcp/simulation/runner.py

TEST CASE:
`evals/run_hackathon_mission.py` (Step 5, lines 138-143)

EXPECTED:
1. When an agent designs and authors a mission (`plan.json` and `mission.json`) for the Hackathon 2026 Urban Fire Rescue problem, the simulation step must generate `skytrack-mission-report.json` dynamically from the authored mission's waypoints, spawn location, speed, camera recording actions, and ball-drop actions.
2. If the authored mission is modified (e.g., different waypoint coordinates, missing `drop-ball`, or wrong altitude), the resulting `skytrack-mission-report.json` must reflect the actual authored trajectory and fail the corresponding rubric criteria.

ACTUAL:
In `evals/run_hackathon_mission.py` lines 140-142:
```python
dest_report = mis_dir / "skytrack-mission-report.json"
if FIXTURE_REPORT.exists():
    dest_report.write_text(FIXTURE_REPORT.read_text(encoding="utf-8"), encoding="utf-8")
```
The script blindly copies the ground-truth `sample-answer-report.json` fixture over `dest_report` and then scores that copied fixture! Consequently, even if `waypoints` in `run_hackathon_mission.py` were completely broken or empty, `score_hackathon_mission_report(dest_report)` would still evaluate the static fixture and report 100/100 points.

REPRODUCTION STEPS:
1. Inspect `evals/run_hackathon_mission.py` lines 140-142.
2. Observe `dest_report.write_text(FIXTURE_REPORT.read_text(...))` overwriting the mission report with the static reference file.

REPRODUCTION RATE:
100%

EVIDENCE:
- `evals/run_hackathon_mission.py:140-142`

LIKELY FAILURE LAYER:
SIMULATION / EVALUATION_HARNESS

ROOT-CAUSE:
Lack of a dynamic kinematical trajectory simulator in `skytrack_mcp` that compiles an authored `plan.json` + `mission.json` into a time-stepped `skytrack-mission-report.json` when Gazebo headless mode is used.

RECOMMENDED FIX:
1. Implement a deterministic kinematics & event simulator `simulate_mission_to_execution_report(mission_id: str, project_id: str)` in `src/skytrack_mcp/simulation/runner.py` (and expose it or call it from `execute_route_mission` / `run_hackathon_mission.py`).
2. This simulator must read `mission.json` and `plan.json` from `ClientData`, compute the actual flight kinematics from `spawnLocation` (`[203.684, -153.697, 0.452]`) through each `"navigate"`, `"start-recording-video"`, `"drop-ball"`, `"stop-recording-video"` action in `plan.json`, and emit authentic events:
   - `TAKEOFF` (climb to `takeoffAltitude`)
   - `NAVIGATION_STATUS` (sampled along each 3D segment at `targetSpeed` with spawn-relative ENU coordinates `x = world_x - spawn_x, y = world_y - spawn_y, z = world_z`)
   - `WAYPOINT_REACHED` (with world ENU coordinates `[x, y, z]` and `wp_index`)
   - `RECORDING_STARTED` / `RECORDING_STOPPED` (when `start-recording-video` and `stop-recording-video` actions execute)
   - `BALL_DROP` (when `drop-ball` executes, recording spawn-relative ENU coordinates `x = world_x - spawn_x, y = world_y - spawn_y, z = world_z`)
   - `RTL` (return from last waypoint to `spawnLocation` and land)
   - `MISSION_END` (with computed duration and ground speed stats)
3. Remove `FIXTURE_REPORT` copying from `evals/run_hackathon_mission.py` so the report is 100% generated from the authored mission!
4. Also compare the dynamically simulated report against `sample-answer-report.json` to prove the agent's authored mission matches the reference answer's trajectory and score.

ACCEPTANCE TEST:
1. `evals/run_hackathon_mission.py` must NOT copy `FIXTURE_REPORT` to `dest_report`.
2. Modifying a waypoint or removing `drop-ball` in `plan.json` must immediately cause the dynamically generated report to fail the corresponding rubric check.
3. With the valid 7-waypoint Urban Fire Rescue route, the dynamically generated report must score 100.0/100.0 and match the reference answer structure.
