BUG ID: BUG-0003
TITLE: Simulation Stack Container Recreation Failure on World/Vehicle Change & PX4 Gazebo Timeout
SEVERITY: S2 - HIGH
CATEGORY: SIMULATION / DOCKER_STACK
STATUS: OPEN

ENVIRONMENT:
- SkyTrack Version: 1.2.2 (Docker Simulation Stack)
- MCP Commit: f605869
- Files: src/skytrack_mcp/clients/docker_exec.py, src/skytrack_mcp/mcp/tools.py

TEST CASE:
`manage_simulation_stack(action='start', world='warehouse', vehicle='x500_livox_mid_360')` or `tool_skytrack_simulation_restart(world='warehouse')`

EXPECTED:
1. When switching worlds or vehicles, the simulation containers must be cleanly recreated so that the Gazebo container loads the new `.sdf` world and PX4 spawns the matching drone model.
2. PX4 SITL startup should detect Gazebo readiness promptly and connect without 300s timeout loops.

ACTUAL:
1. `start_simulation_stack` in `docker_exec.py` rewrites `docker-compose.yml` and calls `docker compose up -d`.
2. When containers were stopped with `docker compose stop`, `docker compose up -d` does not recreate the running containers with new environment variables unless `--force-recreate` or `down` is used.
3. As observed in testing: `skytrack-simulation-gazebo-1` remained running `default.sdf`, while `skytrack-simulation-px4-1` was restarted with `PX4_GZ_WORLD=warehouse`.
4. In `px4-rc.gzsim`, `check_scene_info()` checks `${gz_command} service -i --service "/world/${PX4_GZ_WORLD}/scene/info"`. Because Gazebo Harmonic runs in headless server mode (`-s`), `/scene/info` is not provided, causing PX4 to block for 300 seconds (`PX4_GZ_TIMEOUT=300`) with `INFO [init] Waiting for Gazebo world...` before failing.
5. Consequently, PX4 fails to reach `px4-rc.mavlink`, MAVLink is never started, and `mavlink-bridge` reports `connected: false` indefinitely.

REPRODUCTION STEPS:
1. Call `tool_skytrack_simulation_restart(world='warehouse')`.
2. Run `docker exec skytrack-simulation-gazebo-1 ps aux`: Observe it still running `default.sdf`.
3. Run `docker logs skytrack-simulation-px4-1`: Observe continuous `Waiting for Gazebo world...` loop.

REPRODUCTION RATE:
100% on world switch.

EVIDENCE:
- `docker exec skytrack-simulation-gazebo-1 ps aux`:
  `ruby /usr/bin/gz sim -r -s -v 1 /var/www/files/px4-gz/worlds/default.sdf`
- `docker-compose.yml`:
  `PX4_GZ_WORLD: warehouse`
- `docker logs skytrack-simulation-px4-1`:
  `INFO [init] Waiting for Gazebo world...` (repeated for 300 attempts)

LIKELY FAILURE LAYER:
SIMULATION / DOCKER_STACK

ROOT-CAUSE:
1. Missing `--force-recreate` flag on `docker compose up -d`.
2. `check_scene_info` in PX4 SITL looks for `/world/.../scene/info` which is unavailable in headless Gazebo server mode. A probe checking `/clock` topic indicates Gazebo readiness reliably.

RECOMMENDED FIX:
1. In `src/skytrack_mcp/clients/docker_exec.py`:
   - In `start_simulation_stack`, pass `["docker", "compose", "-f", str(sim_compose), "up", "-d", "--force-recreate"]` to ensure updated environment variables take effect.
   - Or run `down` before `up -d` on world/vehicle changes.
2. Ensure `/app/px4/etc/init.d-posix/px4-rc.gzsim` uses a robust clock-based readiness check in headless mode.

ACCEPTANCE TEST:
Switching world from `default` to `warehouse` must restart Gazebo with `warehouse.sdf`, PX4 must spawn the model in Gazebo within 10 seconds, MAVLink must initialize, and telemetry must show `connected: true`.
