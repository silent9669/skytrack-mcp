TITLE: Mission Report Harvester Ignores Authentic SkyTrack Mission Report JSON
SEVERITY: S1 - CRITICAL
CATEGORY: REPORT_PARSING
STATUS: OPEN

ENVIRONMENT:
- SkyTrack Version: 1.2.2 (Electron 39.8.10)
- MCP Commit: f605869
- World: warehouse / farm-petersburg / default
- Files: src/skytrack_mcp/report/parser.py, src/skytrack_mcp/mcp/tools.py

TEST CASE:
`tool_skytrack_report_read` / `harvest_flight_report` for completed missions `mis-01M39YY8G8NZXCBMJH8RHH1GWP` and `mis-01M39VXV158DGVPV6TFB8Y8ZBS`.

EXPECTED:
`harvest_mission_report_data` must locate and parse the authentic SkyTrack Mission Report JSON files stored on disk in the mission directory (`mis-<id>/skytrack-mission-report*.json`), which contain:
1. `execution_metadata` (`status`, `duration`, `world`, `mission_id`).
2. `execution_report` array with `status_summary` (`total_waypoints`, `average_ground_speed`, `waypoints_defined`).
3. Detailed chronological `execution_events` (`FLIGHT_MODE_CHANGE`, `NAVIGATION_STATUS`, `WAYPOINT_REACHED`, `PAYLOAD_TRIGGER` with visited coordinates and timestamps).

ACTUAL:
1. `src/skytrack_mcp/report/parser.py` lines 16-80 completely ignores any `skytrack-mission-report*.json` files.
2. Instead, it reads `mission.json`, `plan.json`, checks `media/captures`, and takes an instantaneous snapshot of live MAVLink telemetry (`fetch_live_mavlink_telemetry()`).
3. If telemetry is not streaming at the exact millisecond `harvest_mission_report_data` is called, `telemetry_state` fields (`connected`, `is_armed`, `landed_state`, `flight_mode`, `final_enu_position`) are all `null` or `false`.
4. The output lacks the actual visited waypoint coordinates, event timeline, ground speed, and completion status produced by SkyTrack.

LIKELY FAILURE LAYER:
REPORT_PARSING / ADAPTER

ROOT-CAUSE:
The implementation author synthesized an ad-hoc dictionary schema without discovering the authentic SkyTrack mission report file format already present on disk in `ClientData`.

WHY THIS MATTERS:
Violates `review.md` Section 10: "Mission Report is one of the most important sources of evidence. OPEN IT. READ IT. PARSE IT. Determine which report fields are authoritative." The agent cannot verify visited positions, timing, or payload trigger execution without parsing the true execution events.

RECOMMENDED FIX:
1. Update `src/skytrack_mcp/report/parser.py`:
   - Search for `skytrack-mission-report*.json` in the mission directory.
   - Parse `execution_metadata`, `status_summary`, and `execution_events`.
   - Extract reached waypoints, durations, and payload events.
   - If no native report file is present, fallback gracefully to live telemetry/plan.json.
2. Update `render_markdown_flight_report` to present the timeline of executed events, reached waypoints, and ground speeds.
