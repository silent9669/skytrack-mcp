BUG ID: BUG-0001
TITLE: False Verification in Evaluation Harness and Requirement Evaluator
SEVERITY: S1 - CRITICAL
CATEGORY: VERIFICATION / EVALUATION_HARNESS
STATUS: OPEN

ENVIRONMENT:
- SkyTrack Version: 1.2.2 (Electron 39.8.10)
- MCP Commit: f605869
- World: default / warehouse
- UAV: x500_livox_mid_360 / x500_tennis_balls_no_cam
- File: evals/run_all_evals.py, evals/runner.py, src/skytrack_mcp/report/verification.py

TEST CASE:
`run_all_evals.py` (EVAL 1 through EVAL 5)

EXPECTED:
1. When a mission is dispatched to simulation, the evaluation harness must wait for the drone to execute the flight, reach the target waypoints, and land safely (using `run_mission_and_wait_completion` or observation loops).
2. Requirement verification must evaluate actual flight execution events (`WAYPOINT_REACHED`, `landed_state == 'ON_GROUND'`, collision-free flight trajectory).
3. "Safe Takeoff Altitude" requirement must verify altitude metrics (e.g. `takeoff_altitude >= 1.5m`), NOT `report_data.world == 'default'`.
4. "Collision-Free 3D Trajectory" must verify actual obstacle clearance during flight, NOT `total_planned_waypoints >= 5`.

ACTUAL:
1. `run_all_evals.py` calls `await execute_route_mission(...)` and immediately reads the report within 0.1s without waiting for the drone to take off, fly, or land. The entire 5-scenario evaluation suite completes in 5 seconds without the drone moving in Gazebo.
2. `evaluate_mission_requirements` in `verification.py` lines 78-83 evaluates `min_waypoints` by checking `report_data.get("total_planned_waypoints")` (which is simply parsed from `plan.json`), rather than checking waypoints reached during flight.
3. In `run_eval_1`, the requirement for "Safe Takeoff Altitude" specifies `type: "world"`, which checks whether `report_data.world == 'default'`.
4. In `run_eval_2`, "Collision-Free 3D Trajectory" specifies `type: "min_waypoints"`, claiming collision-free clearance because 6 waypoints were planned in `plan.json`.
5. The harness generates `docs/eval-results.md` asserting "5/5 Evaluated Missions PASSED (100% Verified)" despite no flight having occurred.

REPRODUCTION STEPS:
1. Run `.venv/bin/python -m evals.run_all_evals`.
2. Inspect the runtime: the entire script finishes in ~5 seconds.
3. Check `docs/eval-results.md`: all 5 tests report 100% PASSED with non-authoritative evidence.

REPRODUCTION RATE:
100% (5/5 runs)

LIKELY FAILURE LAYER:
EVALUATION_HARNESS / VERIFICATION

ROOT-CAUSE:
The evaluation script bypassed the closed-loop execution tool `run_mission_and_wait_completion` in favor of fire-and-forget `execute_route_mission`, and the verification matrix checked plan-time JSON metadata instead of real flight execution events.

WHY THIS MATTERS:
Violates `review.md` Section 32: "Treat false positive verification as one of the highest-severity defects." An autonomous agent using this harness would claim mission success even if the drone never armed, crashed on takeoff, or stalled.

RECOMMENDED FIX:
1. Update `evals/run_all_evals.py` to use closed-loop execution (`run_mission_and_wait_completion`) with live telemetry observation.
2. In `src/skytrack_mcp/report/verification.py`, add verification handlers for:
   - `takeoff_altitude`: verify `takeoff_altitude_m >= expected`.
   - `waypoints_reached`: count `WAYPOINT_REACHED` events from flight execution events.
   - `landed_safely`: confirm final state is `ON_GROUND` after flight.
3. Update requirement definitions in all evals to use correct type keys matching actual flight evidence.

ACCEPTANCE TEST:
Run `evals/run_all_evals.py`. It must take at least the real flight time (~30-60s per scenario with live telemetry), wait for `landed_state == 'ON_GROUND'`, and verify visited waypoint coordinates against tolerances using `WAYPOINT_REACHED` events.
