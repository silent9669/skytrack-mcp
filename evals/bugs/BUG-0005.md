BUG ID: BUG-0005
TITLE: Hackathon Evaluator Hardcodes Video Recording Score (18 pts) Without Verifying Action Ordering
SEVERITY: S1 - CRITICAL
CATEGORY: VERIFICATION / RUBRIC_EVALUATOR
STATUS: RESOLVED (Verified in Review Cycle 4 by commit e3d8721)

ENVIRONMENT:
- SkyTrack Version: 1.2.2
- MCP Commit: f0a1850
- File: evals/expected/hackathon_evaluator.py

TEST CASE:
`score_hackathon_mission_report` in `evals/expected/hackathon_evaluator.py` (lines 93-97)

EXPECTED:
Criterion 4 of the SkyTrack Hackathon 2026 rubric ("Ghi hình bao đúng cú thả - bật trước, tắt sau" — 18 points) requires verifying that:
1. The drone is equipped with a camera (e.g. `x500_tennis_balls`) and video recording is started (`start-recording-video` / `RECORDING_STARTED`) BEFORE the firefighting ball is dropped (`drop-ball` / `BALL_DROP`).
2. Video recording is stopped (`stop-recording-video` / `RECORDING_STOPPED`) AFTER the firefighting ball is dropped.
3. If recording is missing, or started after the drop, or stopped before the drop, Criterion 4 must score `0.0` points.

ACTUAL:
In `evals/expected/hackathon_evaluator.py` lines 93-97:
```python
# Criterion 4: Video recording wraps the drop (18 pts)
scores["video_recording_wrapped"] = 18.0
details["video_recording"] = "Verified in mission plan & execution structure"
```
It is unconditionally hardcoded to `18.0` points! Even if a mission has zero camera actions or drops the ball without recording, it still receives 18/18 points.

REPRODUCTION STEPS:
1. Pass a mission report or mission folder with no `start-recording-video` / `stop-recording-video` actions to `score_hackathon_mission_report`.
2. Observe `rubric_scores["video_recording_wrapped"] == 18.0`.

REPRODUCTION RATE:
100%

EVIDENCE:
- `evals/expected/hackathon_evaluator.py:93-97`

LIKELY FAILURE LAYER:
VERIFICATION

RECOMMENDED FIX:
Update `score_hackathon_mission_report(report_json_path: Path, plan_json_path: Optional[Path] = None)` in `evals/expected/hackathon_evaluator.py` to verify Criterion 4 from:
1. Execution events in `report_json_path` (if `RECORDING_STARTED`, `BALL_DROP`, `RECORDING_STOPPED` events are present, verify `idx(RECORDING_STARTED) < idx(BALL_DROP) < idx(RECORDING_STOPPED)`), OR
2. The accompanying `plan.json` in the same mission directory (or embedded action sequence), verifying that `start-recording-video` occurs at an action index strictly before `drop-ball`, and `stop-recording-video` occurs at an action index strictly after `drop-ball`.
3. For the raw `sample-answer-report.json` fixture (where SkyTrack Cloud did not log camera trigger events into `execution_events` unless `plan.json` is alongside it), allow checking `plan.json` if present, or checking `RECORDING_STARTED`/`STOPPED` events in generated reports, and add a unit test in `tests/test_hackathon_benchmark.py` proving that omitting `start-recording-video` or `stop-recording-video` reduces the score by 18 points (from 100.0 to 82.0).

ACCEPTANCE TEST:
`test_rubric_penalizes_missing_video_recording` in `tests/test_hackathon_benchmark.py` must pass, proving that a mission without `start-recording-video` before `drop-ball` and `stop-recording-video` after `drop-ball` scores `0.0` on `video_recording_wrapped`.
